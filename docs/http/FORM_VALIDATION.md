# Wspólny wzorzec formularzy — F-402

DECISION: źródłem walidacji jest Laravel Form Request. Mutacje używają `useForm` i redirect/session errors zgodnie z [kontraktem](REQUESTS_RESPONSES.md) oraz [obsługą błędów](ERROR_HANDLING.md). Nie dodajemy strony ani endpointu walidacji do produkcyjnego routingu.

## Laravel

- Nowy Request mutacji dziedziczy po `App\Http\Requests\MutationRequest`. Abstrakcyjne `authorize(): bool` wymusza jawną decyzję: scoped lookup i Policy operacji. Rola, `can`, hidden input i `exists` nie zastępują Policy ani zgodności relacji. Cudzy/brakujący kontekst daje 404, obca rola 403; nie zamieniamy ich na błąd pola.
- `rules()` waliduje typy przed ograniczeniami wartości. Dla pojedynczego pola stosujemy `bail`, gdy kolejne komunikaty nie pomogą. Laravel `TrimStrings` i `ConvertEmptyStringsToNull` normalizują zwykły tekst; nie przycinamy haseł. `nullable` oznacza świadomie dozwolone NULL, `required` odrzuca puste wejście. Pola liczbowe z HTML mogą być stringami: `integer` waliduje je bez uprzedniego rzutowania. Dopiero poprawne dane mapujemy do typów usługi; nie zamieniamy pustego pola na zero.
- `prepareForValidation()` wykonuje tylko jawne normalizacje kontraktu (np. lowercase email), po `is_string`; nie maskuje błędnych tablic/typów przez rzutowanie. Nie normalizujemy automatycznie każdego pola/identyfikatora. Reguły nazw Unicode, ID, relacji, dat oraz transakcji powstają z funkcjami domenowymi; regex wyłącznie dla nazw osób i klas zgodnie z kontraktem.
- Zapis korzysta z `validated()` / `safe()->only(...)`, nigdy `all()`. Przy zagnieżdżonych obiektach deklarujemy dozwolone klucze (`array:key1,key2`); sama walidacja rodzica `array` nie daje allowlisty jego zawartości. ID aktora i niezmienne relacje pochodzą z autoryzowanego kontekstu.
- Nie nadpisujemy `failedValidation()` ani nie zwracamy ręcznego JSON 422 dla Inertia. Framework przekierowuje i zapisuje błędy w sesji; adapter dzieli pierwszy komunikat na pole w `errors`. Błędy domenowe używają `ValidationException::withMessages(['form' => '…'])`, `conflict` lub konkretnego pola, bez częściowego zapisu. `conflict` wymaga jawnej akcji odświeżenia w stronie funkcji, bez ponowienia mutacji.
- `lang/pl/validation.php` zawiera polskie komunikaty wspólnych reguł i nazwy pól konta. Request dodaje `attributes()` dla swoich pól (w tym ścieżek `assignments.*.…`) oraz `messages()` dla precyzyjnych komunikatów domenowych. Nowa reguła wymaga polskiego komunikatu i testu; plik nie jest pełnym tłumaczeniem wszystkich reguł Laravel. Domyślny locale i `.env.example` to `pl`.
- Nie flashujemy sekretów. Standardowa lista wyjątków Laravel obejmuje `current_password`, `password`, `password_confirmation` — test potwierdza ich brak w old input. Nowe nazwy sekretów wymagają rozszerzenia `dontFlash` w konfiguracji wyjątków. Nie przekazujemy całego old input do props ani nie logujemy formularza.

## React

Przykład kompletny: `tests/Fixtures/Forms/probe.tsx`. Jest dostępny wyłącznie w harnessie testowym, poza resolverem i trasami produkcyjnymi.

1. `useForm({...})` przechowuje wartości i `errors`. Body używa snake_case, pusty kontrolowany input ma `''`; normalizacja NULL odbywa się na serwerze. `noValidate` pozwala pokazać spójne błędy serwera zamiast blokowania wysyłki przez komunikaty przeglądarki. Etykiety i `required` nadal opisują obowiązkowe pola.
2. `FormField` przyjmuje stabilny, unikalny w dokumencie `id`, `label`, `hint?`, `error?` i funkcję `children`. Wynikowe atrybuty przekazujemy do faktycznego kontrolowanego Input/textarea/triggera Select: `aria-invalid`, `aria-describedby` łączą hint oraz błąd. Label nie jest placeholderem. Nie dodajemy drugiego `InputError` wewnątrz pola.
3. `ErrorSummary` otrzymuje pełne `form.errors` oraz mapę klucza błędu → `{id,label}`. Po nowej odpowiedzi z błędami fokus trafia do podsumowania (`role=alert`). Link aktywowany myszą lub Enter przenosi fokus na pole. Błędy `form`, `conflict` i niezmapowane pozostają tekstem; nie znikają i nie mają fikcyjnych linków. Nie deduplikujemy komunikatów różnych pól. Nie renderujemy HTML komunikatu.
4. `SubmitButton processing={form.processing}` ma stałą nazwę, spinner dekoracyjny, `aria-busy` i disabled. Formularz również ma `aria-busy`; handler sprawdza `processing`. To ochrona UX; serwer nadal rozstrzyga autoryzację, wersję i unikalność. Brak automatycznego retry po timeout, 419 lub 503.
5. Po błędzie zachowujemy niesekretne wartości: nie wywołujemy `reset()` całego formularza w `onError` / `onFinish`. Hasła czyścimy w `onFinish` dla każdego wyniku; formularz z sekretami nie używa klucza remember. Przy bezpiecznym sukcesie ewentualny reset i flash określa funkcja. Nie utrwalamy haseł w history state/localStorage.
6. Gdy kilka formularzy współistnieje, każdy ma oddzielny `useForm`, identyfikatory DOM i własne podsumowanie. Używamy błędów danego `useForm`, nie globalnego worka strony. Przy named error bags uzgadniamy nazwę między Request i opcją `errorBag` wizyty — nie mieszamy obu mechanizmów przypadkowo.

## Testy i uruchomienie

`php artisan test --filter='FormValidationTest|FormInputTest'` nie wymaga bazy domenowej. Techniczne routes ładuje wyłącznie test; test sprawdza również ich brak po normalnym boot aplikacji. Sukces zapisuje w sesji tylko niesekretny techniczny marker, odmowa i walidacja nie wykonują efektu. Policy rekordu, S/T/W oraz transakcje muszą być testowane przy przyszłych mutacjach — fixture ich nie udaje.

`npm test` uruchamia Vitest/RTL. `npm run test:e2e:forms` uruchamia Chromium, PHP test server i Vite na portach 8187/5187; wymaga zainstalowanych PHP 8.3+, Node 22.22.2+ (22.x) i `npx playwright install chromium`. Do pełnego porównania typografii wcześniej `composer wayfinder` i `npm run build` (lokalne fonty). `FORMS_PHP_COMMAND` i `FORMS_VITE_COMMAND` mogą zastąpić komendy serwerów procesami kontenerowymi; muszą zachować porty i dla PHP środowisko testowe z konfiguracji Playwright. Serwer używa sesji plikowej, cache array, stałego jawnego klucza wyłącznie testowego, bez domenowej bazy. Nie uruchamiać go jako serwera aplikacji. Standardowa produkcyjna aplikacja nie odczytuje `tests/Fixtures`.

Nowe zależności są wyłącznie developerskie: Vitest 5 (peer Vite 8, Node ≥22.12), RTL 16 (peer React 19) z DOM 10/user-event 14/jest-dom 6, jsdom 31 (Node ≥22.22.2), Playwright 1.65 (Node ≥20). DECISION: minimalna wersja developerskiego Node 22 wzrasta do 22.22.2 z powodu jsdom 31; `engines` egzekwuje tę zgodność. Runtime aplikacji nie wymaga Node. Rozwiązanie sprawdzane na Node 22.23.5. Licencje: MIT, jsdom MIT, Playwright Apache-2.0; nie dodajemy runtime walidatora ani klienta API. Dokładne wersje utrwala `package-lock.json`. To minimalny harness wymagany przez F-402, nie deklaracja ukończenia szerszego F-501.
