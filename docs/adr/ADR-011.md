# ADR-011 — Temporal Grade Context and Gradebook Columns

## Status

Przyjęty w dokumentacji w ramach mandatu architektonicznego; realizacja fundamentu F-003 do przeglądu; interfejsy HTTP w kolejnych funkcjach. Założenia domenowe wymienione jawnie; nie jest to zmiana zatwierdzonego stacku. Data: 2026-11-15. Otwarte decyzje (hosting, produkcyjna retencja, plusy/minusy) nie są przez ten ADR akceptowane.

## Kontekst

Figma17:620 pokazuje wspólne kolumny i puste komórki; pojedyncze users.class_id nie zachowuje historii transferów.

## Decyzja

Roczne klasy, termy, enrollmenty z datami, assignment per teacher/class/subject/term i assessment jako kolumna; grade przechowuje snapshot pól oceny.

## Uzasadnienie

Pozwala odtworzyć klasę i okres, odróżnić brak oceny od braku kolumny i liczyć rzeczywistą wagę.

## Rozważone alternatywy

Grupowanie kolumn po samej dacie lub users.class_id — niejednoznaczne; rozbudowany moduł egzaminów — nadmierny.

## Konsekwencje

Współprowadzenie przyjęte jako ASSUMPTION; jeden grade per enrollment+assessment także trashed, korekta pól jednostkowa.

## Ryzyka

Rozbieżność nagłówka i indywidualnej korekty; UI oznacza override, średnia używa grade.weight.

Szczegóły normatywne: [dokument źródłowy](../database/SCHEMA.md). Zmiana istotnego zachowania wymaga aktualizacji tego ADR i powiązanych kontraktów/specyfikacji.

## Realizacja F-003

Modele i relacje, blokady usług, fixture i testy MariaDB wykonane 2026-11-15. Konfiguracja kalendarza jest addytywna: daty istniejących lat/termów nie są edytowane przez CLI; zamknięcie jest nieodwracalne. Stały techniczny wiersz calendar_configuration serializuje także konfigurację pierwszego roku. Techniczne pola Fortify i akcesor name zachowane dla zgodności startera; [szczegóły schematu](../database/SCHEMA.md#realizacja-f-003-2026-11-15).
