# F-306 — Class Management

## 1. Status

Planned

## 2. Priorytet

P0

## 3. Cel

Zarządzać klasami rocznikowymi i członkostwem uczniów.

## 4. Historia użytkownika

Jako administrator chcę zarządzać klasami rocznikowymi i członkostwem uczniów, aby móc bezpiecznie realizować zadania dziennika.

## 5. Zakres

Lista/create/rename/archive klas, enrollment create/end/transfer; rok przez F-003.

## 6. Zależności

[F-007](F-007.md), [F-402](F-402.md), [F-003](F-003.md)

## 7. Odniesienia Figma

[20:2220](https://www.figma.com/design/QmOrJFZWMpJTHC5Q8s7Ltp?node-id=20-2220); [24:1180](https://www.figma.com/design/QmOrJFZWMpJTHC5Q8s7Ltp?node-id=24-1180) Mapowanie wariantów ról i jawne luki: [SCREEN_MAP](../design/SCREEN_MAP.md); referencja współdzielona nie oznacza dedykowanej ramki admina.

## 8. Uprawnienia

Wyłącznie admin; User/School Policies. Ochrona ostatniego admina i historycznych relacji obowiązuje niezależnie od UI.

## 9. Reguły biznesowe

Unique(year,name); transfer D kończy stary D−1 i tworzy nowy D, bez przenoszenia ocen. Szczegóły: [reguły domenowe](../database/BUSINESS_RULES.md).

## 10. Baza danych

school_classes,academic_years,student_enrollments. Zmiany tylko migracjami.

## 11. Implementacja Laravel

Admin/EnrollmentController@store; Admin/EnrollmentController@update; Admin/SchoolClassController@destroy; Admin/SchoolClassController@index; Admin/SchoolClassController@store; Admin/SchoolClassController@update [Pełne trasy](../http/ROUTES.md).

## 12. Kontrakt Inertia

admin/classes/index; ClassManagementProps; redirect admin.classes.index [Typy i redirecty](../http/REQUESTS_RESPONSES.md).

## 13. Implementacja React

Strony zgodnie z kontraktem powyżej; komponenty z [COMPONENTS](../design/COMPONENTS.md), useForm dla mutacji, URL dla filtrów. Nie powielać serwisów domenowych w React.

## 14. Tailwind / UI

Semantyczne tokeny [DESIGN_SYSTEM](../design/DESIGN_SYSTEM.md), mobile 390/tablet 1024/desktop 1440 według [RESPONSIVENESS](../design/RESPONSIVENESS.md); stany pending/error/empty i fokus.

## 15. Walidacja

ClassFilterRequest, DeleteClassRequest, StoreClassRequest, StoreEnrollmentRequest, UpdateClassRequest, UpdateEnrollmentRequest — reguły pól w [kontrakcie](../http/REQUESTS_RESPONSES.md).

## 16. Obsługa błędów

[ERROR_HANDLING](../http/ERROR_HANDLING.md): błąd zakresu403/404, walidacja przez redirect/errors; brak częściowego zapisu i automatycznego ponawiania mutacji.

## 17. Przypadki brzegowe

Zmiana dat poza istniejącymi ocenami, nakładające enrollmenty, archiwizacja aktywnej klasy.

## 18. Bezpieczeństwo

Serwer ponownie sprawdza zakres, także przy bezpośrednim żądaniu. Props tylko z allowlisty; brak haseł i danych obcych kont. Nie ufać can ani hidden input.

## 19. Kryteria akceptacji

**Mając** wymagane zależności i dane testowe, **gdy** wykonano funkcję w opisanym zakresie, **wtedy**: Transfer zachowuje stare grade enrollment; dwa równoległe zapisy nie tworzą nakładających członkostw.

**Mając** błędny kontekst lub dane, **gdy** operacja zostanie podjęta, **wtedy** brak nieautoryzowanego efektu i komunikat zgodny z sekcją błędów.

## 20. Testy

Feature temporal relationships/transactions; E2E admin class and enrollment.

## 21. Definition of Done

Kryteria z sekcji19 udowodnione testami, zależności działają, dokumentacja/kontrakty aktualne; [wspólne DoD](../testing/DEFINITION_OF_DONE.md). Dla brakujących ramek nie deklarować pełnej zgodności wizualnej; rozstrzygnąć lukę przed Done.
