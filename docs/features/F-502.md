# F-502 — GitHub Actions CI

## 1. Status

Planned

## 2. Priorytet

P1

## 3. Cel

Automatycznie blokować regresje na PR.

## 4. Historia użytkownika

Jako użytkownik chcę automatycznie blokować regresje na PR, aby mieć odtwarzalne środowisko rozwoju.

## 5. Zakres

Jobs backend/frontend/E2E oraz lekka walidacja docs; brak deploy na nieznany serwer.

## 6. Zależności

[F-501](F-501.md)

## 7. Odniesienia Figma

Nie dotyczy: funkcja techniczna bez własnego ekranu.

## 8. Uprawnienia

Operator repozytorium/środowiska; ta funkcja nie nadaje użytkownikowi uprawnień domenowych.

## 9. Reguły biznesowe

Dokumentacja-only nie uruchamia pełnego E2E; required aggregate check nie może wisieć jako skipped. Szczegóły: [reguły domenowe](../database/BUSINESS_RULES.md).

## 10. Baza danych

MariaDB 11.4 service w job integracyjnym. Zmiany tylko migracjami.

## 11. Implementacja Laravel

Konfiguracja i pliki środowiska zgodnie z dokumentem źródłowym; nie dodawać publicznych tras dla operacji operatorskich. [Pełne trasy](../http/ROUTES.md).

## 12. Kontrakt Inertia

Brak samodzielnego kontraktu strony. Integracja korzysta z SharedProps i kontraktów funkcji wywołującej. [Typy i redirecty](../http/REQUESTS_RESPONSES.md).

## 13. Implementacja React

Nie dotyczy bezpośrednio; smoke UI weryfikuje zbudowany artefakt.

## 14. Tailwind / UI

Bez nowego UI.

## 15. Walidacja

Weryfikacja wejścia i konfiguracji według [źródła](../infrastructure/CI_CD.md); nie pomijać kontroli typów ani relacji.

## 16. Obsługa błędów

Błąd instalacji/build/migracji kończy etap; brak deklaracji gotowości bez pozytywnego logu.

## 17. Przypadki brzegowe

PR z forka bez sekretów, cache starego lockfile, błąd migracji.

## 18. Bezpieczeństwo

Bez sekretów w manifestach, obrazach, logach ani fixture produkcyjnych.

## 19. Kryteria akceptacji

**Mając** wymagane zależności i dane testowe, **gdy** wykonano funkcję w opisanym zakresie, **wtedy**: PR kodu uruchamia kontrole i nie może przejść po błędzie; PR docs kończy check dokumentacji bez pełnego E2E.

**Mając** błędny kontekst lub dane, **gdy** operacja zostanie podjęta, **wtedy** brak nieautoryzowanego efektu i komunikat zgodny z sekcją błędów.

## 20. Testy

Próbny PR z kontrolowanym błędem i poprawką; zapis URL/logów uruchomienia.

## 21. Definition of Done

Kryteria z sekcji19 udowodnione testami, zależności działają, dokumentacja/kontrakty aktualne; [wspólne DoD](../testing/DEFINITION_OF_DONE.md). Nie deklarować uruchomienia bez rzeczywistego wyniku.
