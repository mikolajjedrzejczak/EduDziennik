# F-203 — Class Gradebook

## 1. Status

Planned

## 2. Priorytet

P0

## 3. Cel

Prowadzić siatkę ocen i roster uczniów.

## 4. Historia użytkownika

Jako nauczyciel; współdzielony zakres także dla pozostałych uprawnionych ról chcę prowadzić siatkę ocen i roster uczniów, aby móc bezpiecznie realizować zadania dziennika.

## 5. Zakres

Dziennik teacher/admin, szczegóły ucznia, kolumny assessments create/delete puste; backend wspólny.

## 6. Zależności

[F-202](F-202.md), [F-306](F-306.md), [F-103](F-103.md), [F-104](F-104.md)

## 8. Uprawnienia

Wymagany zakres [RBAC](../product/RBAC.md): S dla ucznia, T dla nauczyciela, pełny zakres admina; każda mutacja ocen dodatkowo W. Dla elementów wspólnych rola nie zastępuje Policy rekordu.

## 9. Reguły biznesowe

Assessment zachowuje kontekst; jedna komórka enrollment+assessment; empty≠0; średnia obejmuje wszystkie kolumny. Szczegóły: [reguły domenowe](../database/BUSINESS_RULES.md).

## 10. Baza danych

assessments, enrollments, grades, assignments; bez oceny0. Zmiany tylko migracjami.

## 13. Implementacja React

Strony zgodnie z kontraktem powyżej; komponenty z [COMPONENTS](../design/COMPONENTS.md), useForm dla mutacji, URL dla filtrów. Nie powielać serwisów domenowych w React.

## 14. Tailwind / UI

Semantyczne tokeny [DESIGN_SYSTEM](../design/DESIGN_SYSTEM.md), mobile 390/tablet 1024/desktop 1440 według [RESPONSIVENESS](../design/RESPONSIVENESS.md); stany pending/error/empty i fokus.

## 15. Walidacja

ClassFilterRequest, DeleteAssessmentRequest, GradeFilterRequest, GradebookFilterRequest, StoreAssessmentRequest — reguły pól w [kontrakcie](../http/REQUESTS_RESPONSES.md).

## 16. Obsługa błędów

[ERROR_HANDLING](../http/ERROR_HANDLING.md): błąd zakresu403/404, walidacja przez redirect/errors; brak częściowego zapisu i automatycznego ponawiania mutacji.

## 17. Przypadki brzegowe

Ponad10 kolumn/uczniów, transfer, brak ocen, archived assessment bez grade.

## 18. Bezpieczeństwo

Serwer ponownie sprawdza zakres, także przy bezpośrednim żądaniu. Props tylko z allowlisty; brak haseł i danych obcych kont. Nie ufać can ani hidden input.

## 19. Kryteria akceptacji

**Mając** wymagane zależności i dane testowe, **gdy** wykonano funkcję w opisanym zakresie, **wtedy**: Desktop pokazuje kolumny, mobile karty; nowa kolumna ma puste komórki bez zmiany średnich; usunięcie kolumny z historią jest odrzucone.

**Mając** błędny kontekst lub dane, **gdy** operacja zostanie podjęta, **wtedy** brak nieautoryzowanego efektu i komunikat zgodny z sekcją błędów.

## 20. Testy

Feature assessment CRUD subset i zagnieżdżenia; RTL karty/tabela; E2E390/1440.

## 21. Definition of Done

Kryteria z sekcji19 udowodnione testami, zależności działają, dokumentacja/kontrakty aktualne; [wspólne DoD](../testing/DEFINITION_OF_DONE.md). Dla brakujących ramek nie deklarować pełnej zgodności wizualnej; rozstrzygnąć lukę przed Done.
