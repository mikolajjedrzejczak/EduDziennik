# F-304 — User Editing

## 1. Status

Planned

## 2. Priorytet

P0

## 3. Cel

Edytować konto bez naruszenia historii i dostępu.

## 4. Historia użytkownika

Jako administrator chcę edytować konto bez naruszenia historii i dostępu, aby móc bezpiecznie realizować zadania dziennika.

## 5. Zakres

Imię/nazwisko/email/status/rola i opcjonalny reset hasła; relacje przez F-306/F-308.

## 6. Zależności

[F-303](F-303.md)

## 8. Uprawnienia

Wyłącznie admin; User/School Policies. Ochrona ostatniego admina i historycznych relacji obowiązuje niezależnie od UI.

## 9. Reguły biznesowe

Role z historycznymi relacjami chronione; utrata statusu/roli/reset hasła odbiera sesje; ostatni admin chroniony. Szczegóły: [reguły domenowe](../database/BUSINESS_RULES.md).

## 10. Baza danych

users,sessions,domain_locks; relacje tylko do kontroli. Zmiany tylko migracjami.

## 11. Implementacja Laravel

Admin/UserController@edit; Admin/UserController@update [Pełne trasy](../http/ROUTES.md).

## 12. Kontrakt Inertia

admin/users/edit; UserFormProps; redirect admin.users.show [Typy i redirecty](../http/REQUESTS_RESPONSES.md).

## 13. Implementacja React

Strony zgodnie z kontraktem powyżej; komponenty z [COMPONENTS](../design/COMPONENTS.md), useForm dla mutacji, URL dla filtrów. Nie powielać serwisów domenowych w React.

## 14. Tailwind / UI

Semantyczne tokeny [DESIGN_SYSTEM](../design/DESIGN_SYSTEM.md), mobile 390/tablet 1024/desktop 1440 według [RESPONSIVENESS](../design/RESPONSIVENESS.md); stany pending/error/empty i fokus.

## 15. Walidacja

UpdateUserRequest — reguły pól w [kontrakcie](../http/REQUESTS_RESPONSES.md).

## 16. Obsługa błędów

[ERROR_HANDLING](../http/ERROR_HANDLING.md): błąd zakresu403/404, walidacja przez redirect/errors; brak częściowego zapisu i automatycznego ponawiania mutacji.

## 17. Przypadki brzegowe

Dwie równoległe degradacje adminów, email innego konta, puste password.

## 18. Bezpieczeństwo

Serwer ponownie sprawdza zakres, także przy bezpośrednim żądaniu. Props tylko z allowlisty; brak haseł i danych obcych kont. Nie ufać can ani hidden input.

## 19. Kryteria akceptacji

**Mając** wymagane zależności i dane testowe, **gdy** wykonano funkcję w opisanym zakresie, **wtedy**: Puste hasło nie zmienia hasha; dezaktywacja usuwa sesje; równoczesne żądania nie zostawiają0 adminów.

**Mając** błędny kontekst lub dane, **gdy** operacja zostanie podjęta, **wtedy** brak nieautoryzowanego efektu i komunikat zgodny z sekcją błędów.

## 20. Testy

Feature locks/session revocation/unique; E2E edit status.

## 21. Definition of Done

Kryteria z sekcji19 udowodnione testami, zależności działają, dokumentacja/kontrakty aktualne; [wspólne DoD](../testing/DEFINITION_OF_DONE.md). Dla brakujących ramek nie deklarować pełnej zgodności wizualnej; rozstrzygnąć lukę przed Done.
