# F-501 — Automated Testing

## 1. Status

Planned

## 2. Priorytet

P0

## 3. Cel

Zapewnić działający szkielet testów od początku.

## 4. Historia użytkownika

Jako użytkownik chcę zapewnić działający szkielet testów od początku, aby mieć odtwarzalne środowisko rozwoju.

## 5. Zakres

PHPUnit/MariaDB, Vitest/RTL i Playwright fixtures; scenariusze rozwijane wraz z każdą funkcją.

## 6. Zależności

[F-001](F-001.md), [F-002](F-002.md), [F-003](F-003.md)

## 7. Odniesienia Figma

Nie dotyczy: funkcja techniczna bez własnego ekranu.

## 8. Uprawnienia

Operator repozytorium/środowiska; ta funkcja nie nadaje użytkownikowi uprawnień domenowych.

## 9. Reguły biznesowe

Nie czekać do końca projektu na testy; brak testów lustrzanych i fałszywych sukcesów. Szczegóły: [reguły domenowe](../database/BUSINESS_RULES.md).

## 10. Baza danych

Dedykowana baza edudziennik_test; reset wyłącznie testowej bazy. Zmiany tylko migracjami.

## 11. Implementacja Laravel

Konfiguracja i pliki środowiska zgodnie z dokumentem źródłowym; nie dodawać publicznych tras dla operacji operatorskich. [Pełne trasy](../http/ROUTES.md).

## 12. Kontrakt Inertia

Brak samodzielnego kontraktu strony. Integracja korzysta z SharedProps i kontraktów funkcji wywołującej. [Typy i redirecty](../http/REQUESTS_RESPONSES.md).

## 13. Implementacja React

Nie dotyczy bezpośrednio; smoke UI weryfikuje zbudowany artefakt.

## 14. Tailwind / UI

Bez nowego UI.

## 15. Walidacja

Weryfikacja wejścia i konfiguracji według [źródła](../testing/TEST_STRATEGY.md); nie pomijać kontroli typów ani relacji.

## 16. Obsługa błędów

Błąd instalacji/build/migracji kończy etap; brak deklaracji gotowości bez pozytywnego logu.

## 17. Przypadki brzegowe

Flaky czas/datowanie, zależność od kolejności, SQLite maskujący MariaDB.

## 18. Bezpieczeństwo

Bez sekretów w manifestach, obrazach, logach ani fixture produkcyjnych.

## 19. Kryteria akceptacji

**Mając** wymagane zależności i dane testowe, **gdy** wykonano funkcję w opisanym zakresie, **wtedy**: Runner każdego rodzaju wykonuje sensowny test infrastruktury/komponentu, a autoryzacja i rollback mają testy przy realizacji funkcji.

**Mając** błędny kontekst lub dane, **gdy** operacja zostanie podjęta, **wtedy** brak nieautoryzowanego efektu i komunikat zgodny z sekcją błędów.

## 20. Testy

Sam harness: izolacja baz, deterministyczny zegar, raporty; końcowe suites wg TEST_STRATEGY.

## 21. Definition of Done

Kryteria z sekcji19 udowodnione testami, zależności działają, dokumentacja/kontrakty aktualne; [wspólne DoD](../testing/DEFINITION_OF_DONE.md). Nie deklarować uruchomienia bez rzeczywistego wyniku.
