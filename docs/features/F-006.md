## 8. Uprawnienia

Wymagany zakres [RBAC](../product/RBAC.md): S dla ucznia, T dla nauczyciela, pełny zakres admina; każda mutacja ocen dodatkowo W. Dla elementów wspólnych rola nie zastępuje Policy rekordu.

## 9. Reguły biznesowe

Zmienne Figmy mają pierwszeństwo przed nieaktualną próbką tekstową; success=#137537. Szczegóły: [reguły domenowe](../database/BUSINESS_RULES.md).

## 10. Baza danych

Brak tabel; theme CSS nie jest trwałym źródłem danych domenowych. Zmiany tylko migracjami.

## 11. Implementacja Laravel

Wspólny mechanizm integrują kolejne kontrolery; nie dodawać sztucznej trasy tylko dla komponentu lub walidacji. [Pełne trasy](../http/ROUTES.md).

## 12. Kontrakt Inertia

Brak samodzielnego kontraktu strony. Integracja korzysta z SharedProps i kontraktów funkcji wywołującej. [Typy i redirecty](../http/REQUESTS_RESPONSES.md).

## 13. Implementacja React

Strony zgodnie z kontraktem powyżej; komponenty z [COMPONENTS](../design/COMPONENTS.md), useForm dla mutacji, URL dla filtrów. Nie powielać serwisów domenowych w React.

## 14. Tailwind / UI

Semantyczne tokeny [DESIGN_SYSTEM](../design/DESIGN_SYSTEM.md), mobile 390/tablet 1024/desktop 1440 według [RESPONSIVENESS](../design/RESPONSIVENESS.md); stany pending/error/empty i fokus.

## 15. Walidacja

Weryfikacja wejścia i konfiguracji według [źródła](../http/REQUESTS_RESPONSES.md); nie pomijać kontroli typów ani relacji.

## 16. Obsługa błędów

[ERROR_HANDLING](../http/ERROR_HANDLING.md): błąd zakresu403/404, walidacja przez redirect/errors; brak częściowego zapisu i automatycznego ponawiania mutacji.

## 17. Przypadki brzegowe

Placeholder musi mieć kontrast; chip interaktywny potrzebuje większego hit target niż grafika.

## 18. Bezpieczeństwo

Serwer ponownie sprawdza zakres, także przy bezpośrednim żądaniu. Props tylko z allowlisty; brak haseł i danych obcych kont. Nie ufać can ani hidden input.

## 19. Kryteria akceptacji

**Mając** wymagane zależności i dane testowe, **gdy** wykonano funkcję w opisanym zakresie, **wtedy**: Button/Input/GradeChip odpowiadają potwierdzonym wariantom i używają semantycznych tokenów; fokus działa klawiaturą.

**Mając** błędny kontekst lub dane, **gdy** operacja zostanie podjęta, **wtedy** brak nieautoryzowanego efektu i komunikat zgodny z sekcją błędów.

## 20. Testy

RTL stany/fokus, kontrast par kolorów, porównanie komponentów z MCP.

## 21. Definition of Done

Kryteria z sekcji19 udowodnione testami, zależności działają, dokumentacja/kontrakty aktualne; [wspólne DoD](../testing/DEFINITION_OF_DONE.md). Dla brakujących ramek nie deklarować pełnej zgodności wizualnej; rozstrzygnąć lukę przed Done.


## 22. Raport realizacji — 2026-11-15

FACT: `resources/css/tokens.css` mapuje kompletną tabelę Semantic/Light i aliasy shadcn; `forms.css` korzysta z tych samych wartości. Tailwind zachowuje siatkę 4 px, promienie 4/6/8/12 px, typografię oraz efekty focus/overlay. `cn` rozpoznaje semantyczne rozmiary tekstu, aby kolory nie usuwały klas typografii. Public Sans 400/500/600/700, latin i latin-ext, jest pobierany w buildzie i serwowany lokalnie przez istniejącą integrację `@fonts` z `font-display: swap`. Bez nowych zależności i zmian lockfile.

FACT: Button primary/secondary/ghost/destructive, aliasy startera default/outline/link, disabled i loading (`aria-busy`, natywna blokada akcji); SubmitButton deleguje stan do Button. Input tekst/password/search/date i Select korzystają z tokenów, wysokości 48/40 px oraz widocznego fokusu. FormField nadal odpowiada za label/hint/error i ARIA; nie powstał drugi mechanizm walidacji. PasswordInput ma ikonę 18 px i cel dotyku 44 px. GradeChip 1–6 ma rozmiary S/M/L, czytelną cyfrę, dostępny opis, tryb odczytu/linku/przycisku i cel interakcji min. 44 px. Typ GradeValue ma wspólną definicję w `types/grades.ts`.

VERIFIED: MCP `get_design_context` ze screenshotami oraz `get_variable_defs` dla 4:99, 5:228, 4:209; Auto Layout i wszystkie warianty tych zestawów odczytane. Grade 5/6 i success używają #137537. Loader Button jest lokalnym SVG pobranym z MCP; nie ma tymczasowych URL w aplikacji. Pozostałe ikony kontrolek korzystają z istniejącego Lucide.

DECISION/adaptacje do przeglądu: fokus używa outline 2 px oraz Focus/Ring zamiast powiększać border i przesuwać treść; wariant destrukcyjny hover zachowuje token error (czarny fallback z wygenerowanego kodu nie zastępuje zmiennej). Native Date zachowuje semantykę i kontrolkę kalendarza przeglądarki. GradeChip deleted = przekreślenie i opis, differsFromAssessment = gwiazdka i opis; tych stanów nie przedstawia zestaw 4:209. Ich akceptacja wizualna pozostaje OPEN QUESTION. Dodaj/pusty slot należy do integracji dziennika, poza zakresem ocen 1–6. Puste pole ma czytelny placeholder; empty list/page nie jest stanem tego prymitywu.

FACT: MVP renderuje Light również przy systemowym Dark lub starej preferencji; nie wdrożono trybu Dark. Zachowano API preferencji startera na potrzeby przyszłej integracji. Nie dodano tras produkcyjnych, kontrolerów, danych domenowych ani mutacji. Istniejący techniczny harness testowy formularzy rozszerzono o prymitywy; jego trasy są rejestrowane wyłącznie przez testy. Uprawnienia rekordów i ponowna walidacja serwera pozostają obowiązkiem wywołującej funkcji.

VERIFIED — kontrole lokalne w kontenerach Node 22.23.5 i PHP 8.3.36:

- Instalacja `npm ci` i `composer install` z istniejących lockfiles, `composer wayfinder`.
- `npm run test:unit`: 32 testy (RTL stanów, fokusu, obsługi klawiaturą i blokady pending, regresja cn, 18 par kontrastu tekstu ≥4,5:1). Disabled pozostaje wyłączony z wymogu kontrastu tekstu; placeholder korzysta z text-secondary.
- `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run build`: sukces. Dostosowane prymitywy są objęte lintem i formatowaniem; wygenerowany raport Playwright jest pomijany jako artefakt.
- `php artisan test --filter=FormValidationTest`: 4 testy / 22 asercje, w tym odmowa wykonania przy sfałszowanym kontekście i brak tras fixture w aplikacji. W tym worktree nie ma `.env`; na potrzeby testów podmontowano `.env.example` i przekazano jawny techniczny APP_KEY, bez tworzenia sekretów produktu.
- `npm run test:e2e`: 18 testów Chromium, 320/390/1024/1440 px. Formularze: walidacja, pending, fokus, brak poziomego przepełnienia; prymitywy: geometria, tokeny, hover, fokus, cel chipu ≥44px, Select klawiaturą i powrót fokusu; zbudowana aplikacja: logowanie, 419/429 bez ponowienia oraz Light przy starej preferencji Dark i lokalny font 700 z polskimi znakami. Zrzuty w `test-results/playwright/` i raport `playwright-report/index.html` (artefakty nieśledzone).
- Obejrzano zrzuty komponentów dla 390/1024/1440 i porównano z trzema zestawami MCP: kolory, obrysy, promienie, rozmiary grafiki, typografia i kontrolki. Harness zawija zestaw w dostępnej szerokości, nie jest kopią osobnego ekranu aplikacji.

Ograniczenia: bez pełnego zestawu testów domenowych MariaDB (brak zmian backendu, schematu i chronionych danych). Nie przeprowadzono manualnego zoom 200%, testów Safari/Firefox ani pełnego audytu WCAG. Responsive reflow320px, reduced motion i klawiaturę sprawdza Chromium. Nie utworzono nowych pełnych ekranów mobile/tablet/desktop. Akceptacja adaptacji, integracja kolejnych ekranów i CI F-502 pozostają osobnymi pracami. F-006 nie oznaczono Done; adaptacje i integracje kolejnych ekranów wymagają przeglądu. Dokumentacja pozostaje lokalna i nie jest publikowana przez to zadanie.
