## 22. Raport realizacji — 2026-11-15

FACT: `GET /dashboard` (`DashboardController`) przekierowuje wg roli do `student.dashboard`, `teacher.dashboard`, `admin.dashboard` (`/student`, `/teacher`, `/admin`; `role:` middleware, 403 dla obcej roli, 302 do login dla gościa). Konto o nieznanej roli lub nieaktywne nie dostaje pulpitu (403 / wylogowanie przez `EnsureActiveAccount`). Login nadal prowadzi do `/dashboard`; klient nie wskazuje celu. Pulpity to puste strony (`EmptyState`); dane i panele należą do F-101/F-201/F-301.

FACT: menu buduje serwer (`NavigationService`) i udostępnia jako shared prop `navigation` (`primary`, `secondary`; `null` dla gościa). Zawiera tylko gotowe trasy: Pulpit (trasa pulpitu roli) i Profil i hasło. Klient mapuje allowlistowany klucz ikony; wpisy dziennika, historii, użytkowników i klas dodają funkcje, które wdrażają te trasy. Aktywny link ma `aria-current="page"`. Usunięto starter: shadcn Sidebar, header layout, `sidebarOpen`/cookie `sidebar_state`.

FACT: `AppShell` renderuje dokładnie jedną nawigację: ≥1280 px sidebar 248 px, 768–1279 px rail 72 px, <768 px dolna belka (Start/Profil), bez duplikatu w DOM. Skip link „Przejdź do treści”, `main#main-content`, cele dotyku ≥44 px, safe-area na dolnej belce. Auth layout bez zmian wizualnych (wspólny `Brand`).

DECISION/adaptacje do przeglądu (brak ramek): (1) mobile ma górny pasek z marką i przyciskiem Wyloguj, bo Figma 7:534 nie pokazuje wylogowania w dolnej belce, a kryterium wymaga go na 390 px; (2) dolna belka znika na czas fokusu w polu tekstowym (klawiatura ekranowa na 390 px); (3) blok użytkownika pokazuje rolę, nie klasę/przedmiot („Uczeń, klasa 2A” z Figmy wymaga danych spoza allowlisty F-007); (4) długie nazwisko jest obcinane z pełnym `title`. Konto bez klasy/przypisania widzi ten sam pusty pulpit bez błędu.

VERIFIED — kontenery PHP 8.3 / Node 22, izolowany projekt Compose z MariaDB 11.4:
- `composer test` (PHPUnit): 174 testy, w tym `DashboardTest` (redirect ról, odmowa obcych pulpitów, nawigacja z allowlisty, gość, nieznana rola, konto nieaktywne); Pint i PHPStan bez błędów.
- `npm run test:unit`: 52 testy, w tym 7 RTL powłoki (aria-current, rail/mobile, jedna nawigacja, klawiatura, kolejność fokusu, długie nazwisko, brak menu bez danych serwera); typecheck, lint, format:check bez błędów; `npm run build` sukces.
- `npm run test:e2e`: 32 testy Chromium, w tym projekt `shell` (prawdziwe sesje i baza `edudziennik_test`): trzy role × 390/1024/1440 px — własny pulpit po loginie, szerokość sidebaru 248/72, widoczny i ≥44 px przycisk Wyloguj w obrębie viewportu, brak poziomego przewijania, wylogowanie; odmowa 403 dla obcych pulpitów; kolejność Tab; ukrywanie dolnej belki przy fokusie w polu.
- Porównano zrzuty 390/1024/1440 z Figmą 7:358, 7:534, 38:8368 (pobrane przez MCP `get_screenshot`): układ, kolejność pozycji, szerokości i aktywny stan zgodne. Nie użyto `get_design_context`, więc tokeny wartości pikseli wzięto z `tokens.css`/DESIGN_SYSTEM.

Ograniczenia: zgodność wizualna nie jest potwierdzona pikselowo; nie sprawdzono zoom 200%, 320 px ani Safari/Firefox w tej funkcji. Warianty menu ról z Figmy (Moje oceny, Dziennik itd.) pominięto świadomie — trasy nie istnieją. Nie oznaczono Done; adaptacje wymagają przeglądu.
