## 19. Kryteria akceptacji

**Mając** błędny kontekst lub dane, **gdy** operacja zostanie podjęta, **wtedy** brak nieautoryzowanego efektu i komunikat zgodny z sekcją błędów.

## 22. Stan implementacji

FACT: `admin/users/index` (tabela ≥768 px, karty <768 px, wyszukiwanie `q` po nazwisku/imieniu/e-mailu, filtry rola/status/klasa+semestr, sortowanie `last_name|email|role|created_at`, stronicowanie w URL) i `admin/users/show` (dane konta, zapisy ucznia, przydziały nauczyciela, także cofnięte/historyczne) z trasami `admin.users.index|show`; pozycja „Użytkownicy” w menu serwerowym admina. Kontrakt: [stan integracji F-302](../http/REQUESTS_RESPONSES.md#stan-integracji-f-302).

DECISION: domyślna lista pomija konta usunięte; `status=deleted` pokazuje tylko usunięte (soft delete). Show działa także dla konta usuniętego. Props to allowlista `UserDTO` — brak password, remember_token, 2FA. E-mail widzi wyłącznie admin (cała trasa za `role:admin` + `UserPolicy.view`).

DECISION (adaptacja Figmy): wiersze listy mają dodatkowe `relationSummary` (kolumna „Klasa / przydział” z 19:379). Akcje edycji/usuwania z ramki należą do F-304/F-305 i nie są renderowane; zostaje tylko link do szczegółów. Bottom sheet filtrów (24:404) to na mobile rozwijany panel „Filtry (n)”, nie Sheet. `show` nie ma ramki Figmy — kompozycja read-only wg SCREEN_MAP, wymaga przeglądu wizualnego.

Kontrole (Docker PHP 8.3 + MariaDB 11.4, Node 22): PHPUnit 216 pass (w tym `UserListTest`), Vitest 66 pass (w tym `user-list.test.tsx`), Pint, PHPStan, ESLint, Prettier, `vite build` — bez błędów. NIE wykonano: Playwright, porównania wizualnego z ramkami, testu klawiaturą w przeglądarce. `tsc --noEmit` zgłasza 2 błędy poza zakresem (`pages/admin/subjects/index.tsx`, typ id w Wayfinder).
